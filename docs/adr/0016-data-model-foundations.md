# 0016. Data model foundations

Status: Accepted
Date: 2026-11-01

## Context

The first schema was derived from the API drafts without data requirements. It used free-form text IDs, had no runs or workspaces, and kept file names where evidence would depend on them. Those choices are expensive to change after release. The full model is in [data-model.md](../data-model.md).

## Decision

- **Primary keys are UUIDv7**, generated by Postgres 18's `uuidv7()`. Enrollment tokens are keyed by their hash, and signed statements by their statement ID.
- **File names live only in `delivery_files`.** Audit events, manifests, and receipts never hold them, so a name can be deleted without touching hash-chained evidence.
- **Every delivery belongs to a run,** including a manual one.
- **Signed statements are stored as exact bytes** in one append-only table, never as `JSONB`, which would change them.
- **Agent keys are kept as history** in `agent_identities`, so old statements stay verifiable after a key changes.
- **The design ceiling is 1 million deliveries a day for 13 months.** `deliveries` starts as an ordinary table.

## Alternatives considered

- **`bigint` identity keys:** smaller and fast, but IDs would be guessable, and they would reveal volumes through the API.
- **UUIDv4:** hides creation time, but random inserts scatter across the index.
- **Text IDs:** flexible, but larger, and the database can't check their format.
- **File names inside audit events:** simple, but deleting personal data would break the hash chain.
- **Partitioning from the start:** avoids a later migration, but every install pays for a complexity that most won't need.
- **`JSONB` statements:** queryable, but reordering fields would break signatures.

## Consequences

Evidence and GDPR deletion no longer conflict. Requires Postgres 18 or later. UUIDv7 IDs reveal when a row was created, which is acceptable because timestamps are already visible. If a customer reaches the ceiling, partitioning `deliveries` needs a planned migration and a primary key change. Delivery manifests and receipts must exclude file names, which constrains their payload format.
